# Setup and commands

All paths are relative to the installed skill folder, shown as `<skill>`. Keep real jobs, private profiles, sources, crop previews and outputs outside that folder. Codex prepares the manifests and runs commands on the user's behalf.

PDF layout and crop previews use Python with the dependencies in `requirements.txt`. Excel filling additionally requires Node.js and Codex's `@oai/artifact-tool` package. Use workspace-dependency discovery when available to find those runtimes. Set `CODEX_BUNDLED_NODE_ROOT` or `CODEX_BUNDLED_PYTHON` only when needed for the existing Excel helpers. Do not place machine-specific paths in the public skill.

```text
python -m pip install -r <skill>/requirements.txt
```

## Prepare categorized print sheets

Read the [manifest contract](print-manifest.md) and [layout options](print-layouts.md). Populate a copy of the empty manifest with the reviewed source paths and categories.

Optionally propose exterior-whitespace crops and previews:

```text
python <skill>/assets/package/scripts/prepare_print_views.py --manifest <print-manifest.json> --output <new-crop-directory>
```

The helper writes `print-manifest.proposed.json`, `view-proposals.json`, numbered previews and `contact-sheet.png`. Codex inspects the source/proposed views, accepts only safe crops by setting `reviewed:true`, and uses the resulting manifest for packing. Forms and already-reviewed views are retained. A full-page view is the fallback when a crop is uncertain.

```text
python <skill>/assets/package/scripts/print_sheets.py --manifest <reviewed-print-manifest.json> --output <new-print-directory>
```

Add `--printed-ledger <confirmed-printed-ledger.json>` when the user has identified already-printed pages. Separate PDFs are generated by section, with `print-report.json` and a new prepared-state `print-ledger.json`. No physical print job is dispatched. Reconcile the audit and visually inspect every output sheet before delivery.

## Fill editable forms

Review the separate financial job first:

```text
python <skill>/assets/package/scripts/prepare_receipts.py --job <absolute-job.json> --output <new-check-directory> --check-only
node <skill>/assets/package/forms/fill_forms.mjs --job <absolute-job.json> --output <new-form-directory>
```

The filler writes `reimbursement-<claim_type>-draft.xlsx` and `filled-form-report.json`. Export only its `print_sheets` using an available spreadsheet/PDF tool. Do not export the instructions or unused sheets. Preserve the approved master layout, centered headings, blank signatures and the saved workbook scales. Inspect the exported page geometry, then add exported forms to a separate `forms` section in the print manifest.

The packer accepts exported PDFs, not XLSX. A two-up print revision does not alter the workbook master. Confirm any reduction from the generic approximate 220 × 136 mm cover to the 210 × 136 mm two-up piece.

## Older jobs

```text
python <skill>/assets/package/scripts/pack_by_layout.py --job <absolute-job.json> --output <new-print-directory>
```

This compatibility path retains old ordinary/Ctrip-strip geometry and has the corrected two-cut payment grid. New print workflows should use the manifest tools above. XML/OFD companions are retained metadata and are not parsed or authenticated by these helpers.
